An open protocol for local & self-hosted AI

The layer between the model and everything it can touch.

A model proposes. A runtime disposes. Today the two are wired together ad hoc — every agent framework invents its own tool format, its own permission story, its own way of hoping the model behaves. INTERPLANE standardizes what crosses between them: the model sees only the tools the task needs, the runtime keeps every authority decision, and each run leaves a receipt that can be checked.

01

Neither side's property

INTERPLANE belongs to neither the model side nor the runtime side. Runtimes keep their own tools, policy, approvals, memory, and execution. INTERPLANE standardizes only what crosses — and makes it measurable.

TENSION / A

Catalogs are too big for small models

A 71-tool catalog costs a small local model most of its first-turn context before it has done any work. Bigger prompts, slower turns, worse choices.

TENSION / B

Model output is not permission

A well-formed tool call proves the request is understandable, never that it is authorized. Frameworks that blur that line hand the model keys it should never hold.

TENSION / C

Claims are rarely measured

“Works with your model” usually means someone ran it once. Capability claims need a protocol, a pre-registered gate, and a published result — pass or fail.

02

How a request crosses

Three parties, one direction of authority. The model can ask for anything; only the runtime can say yes.

Model side

The model proposes

It emits a tool call in whatever dialect it speaks. That output is treated as untrusted content, never as an instruction to execute.

→
INTERPLANE

The plane translates & trims

Lenshift parses the dialect. CrossAxis exposes only the tools the task needs. Vectorveil wraps the request in a canonical envelope.

→
Runtime side

The runtime decides

Crossveil carries the request to the runtime's own policy engine. It approves, denies, or asks a human. A denial retried is a denial again.

04

The parts of the plane

Seven components, each with one job. Status labels say plainly what is implemented, what is specified, and what is still only a contract.

Interplane Probe

Measures what an OpenAI-compatible endpoint can actually do — before you trust a word of its documentation.

SHIPPED
Lenshift

Parsers for each model's tool-call dialect, plus result renderers. Speaks openai and qwen35 today; the ajax slot is reserved. It parses — it never executes.

SHIPPED
CrossAxis

Explicit, versioned capability mapping with a deterministic selector: given the catalog and the task, it picks the minimum tool set and records a before-and-after receipt.

SHIPPED
Crossveil

The authority-boundary contract: two runtime callbacks, a lifecycle with fail-closed invariants, and explicit trust classes between content, intent, and authority.

SHIPPED
Bench

The benchmark harness: a paired runner and analyzer that compare a full tool catalog against a CrossAxis selection under a pre-registered protocol.

SHIPPED
RelayLine

The event vocabulary for multi-round exchanges — the words both sides use across a long conversation. A contract so far; transport comes with 0.4.

CONTRACT ONLY
Vectorveil

The envelope and its canonical JSON form — the sealed container a request crosses in. Envelope defined; no transport framework yet, by design.

ENVELOPE ONLY
05

Security, in one paragraph

The model side is untrusted. That is not a warning label; it is the load-bearing assumption every component is built on.

—Lenshift never executes. Parsing a request confers nothing.
—CrossAxis never grants. Selecting a smaller tool set reduces exposure; it is not a permission.
—A valid envelope means “structurally understandable,” never “authorized.”
—The runtime decides, through its own policy engine — and a denial never becomes an authorization by retrying.

0.4Execution Multi-round execution without losing the boundary. SPECIFIED
